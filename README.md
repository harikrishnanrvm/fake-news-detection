# Fake News Detection using Deep Learning

BCA Major Project by Harikrishnan R.

This project tries to classify a news article as **Fake** or **Real** using an LSTM (a type of
deep learning model for text). It also has a traditional Machine Learning baseline (TF-IDF +
Logistic Regression) for comparison, and a small FastAPI web app so the model can actually be
used from a browser.

## Project Overview

The project was built in phases:

1. Dataset collection and exploration
2. Preprocessing (cleaning the text, fixing a data leakage issue found in the dataset)
3. Preprocessing pipeline (turned into reusable code)
4. Baseline model - TF-IDF + Logistic Regression
5. LSTM model
6. Comparing the baseline and the LSTM (which one is actually better, and why)
7. Deployment - a FastAPI backend and a simple Bootstrap frontend (this is what you are reading
   about right now)

All the reports, notebooks and findings from each phase are in the `docs/` folder. If you want to
understand the modeling decisions, start there - this README is only about running the app.

**Important:** the baseline model turned out to perform slightly better than the LSTM on this
dataset (see `docs/model_comparison_report.md` for why). The web app in this phase still uses the
**LSTM** for predictions, since that was asked for specifically in this phase. This does not mean
the LSTM is the "final recommended" model for production - see Phase 6's documents for that
discussion.

## Requirements

- Python 3.11 (project was built and tested on this version)
- Windows, with PowerShell or Git Bash (commands below use Git Bash / `venv/Scripts/`)
- About 500 MB of free disk space for the virtual environment and TensorFlow

## Installation

1. Clone or download this repository.
2. Create a virtual environment and activate it:

   ```
   python -m venv venv
   venv\Scripts\activate
   ```

3. Install the dependencies:

   ```
   pip install -r requirements.txt
   ```

4. Make sure the trained model files already exist under `models/lstm/` (this project does not
   retrain a model when the app starts - it only loads what was already trained in Phase 5). If
   these files are missing, the app will fail to start - see `docs/deployment_guide.md` for what
   to check.

## Running FastAPI

From the project's root folder, with the virtual environment activated:

```
uvicorn api.app:app --reload
```

You should see log lines saying the LSTM model and tokenizer were loaded, followed by
`Application startup complete`. Leave this terminal window open - closing it stops the server.

## Opening the Application

Once the server is running, open a browser and go to:

```
http://127.0.0.1:8000/app
```

(this is the same page as `http://127.0.0.1:8000/static/index.html` - `/app` is just a shorter
link to remember)

You will see a text box where you can paste a news article, a **Predict** button and a **Clear**
button.

Other useful links while the server is running:

- `http://127.0.0.1:8000/docs` - interactive API documentation (Swagger UI)
- `http://127.0.0.1:8000/health` - a simple check that the server is alive
- `http://127.0.0.1:8000/` - a plain JSON welcome message listing the available endpoints

## Running Predictions

**From the browser:** paste an article into the text box and click Predict. After a moment, the
page shows the Prediction (Real/Fake), the Confidence percentage, and which model was used.

Two ready-made sample articles are provided under `demo/` (`fake_article.txt` and
`real_article.txt`) if you want something to paste in quickly for a demo.

**From the API directly**, for example with `curl`:

```
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d "{\"text\": \"paste your article text here, at least 50 characters long\"}"
```

Response looks like:

```json
{
  "prediction": "Real",
  "confidence": 99.73,
  "probability_real": 0.9973,
  "probability_fake": 0.0027,
  "model": "LSTM"
}
```

## Folder Structure

```
fake-news-detection/
    README.md
    requirements.txt
    .gitignore

    config/                 project constants (seeds, paths, model settings)

    dataset/
        raw/                 original CSVs, never modified
        processed/           cleaned/combined/split data generated by scripts

    preprocessing/           text cleaning functions used by both training and the API
    training/                model training code (baseline + LSTM)
    evaluation/              metrics, plots, statistical tests

    models/
        baseline/             saved TF-IDF vectorizer + Logistic Regression model
        lstm/                 saved LSTM model + tokenizer

    notebooks/                one notebook per phase - the actual experiments, run end-to-end

    api/                     FastAPI backend (Phase 7)
        app.py                app setup, startup, error handling
        routes.py             the /, /health, /predict endpoints
        predictor.py          runs the cleaning + prediction pipeline
        model_loader.py       loads the LSTM model/tokenizer once at startup
        schemas.py            request/response formats and validation
        utils.py              small shared helpers

    frontend/                the Bootstrap single-page UI
        index.html
        script.js

    demo/                    sample articles for demonstration
        fake_article.txt
        real_article.txt

    testing/                 automated API tests (pytest) + testing_report.md

    evaluation/experiments.csv   log of every training run (accuracy, F1, etc.)

    docs/                    phase reports, viva notes, deployment guide, user manual
    report/                  figures, tables, screenshots for the dissertation

    logs/                    application logs (not committed to git)
```

## Notes

- This app does **not** retrain any model. It only loads the LSTM that was already trained and
  saved in `models/lstm/` during Phase 5.
- The app is meant for local use / demonstration, not production deployment (no authentication,
  no rate limiting, no HTTPS setup).
- See `docs/deployment_guide.md` if something doesn't start correctly, and `docs/user_manual.md`
  for how to use the web page itself.
