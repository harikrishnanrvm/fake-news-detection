# Deployment Guide

**Phase:** Phase 7 — Deployment and User Interface

This guide explains how to get the Fake News Detection web app running on a fresh machine. It is
written for someone who has this repository already (a guide, an examiner, or myself on a
different laptop) but has not run it before.

---

## 1. Python Version

This project was built and tested with **Python 3.11**. Using a different major version (like
3.9 or 3.13) may cause TensorFlow to fail to install, since TensorFlow only supports specific
Python versions at a time. Check your version with:

```
python --version
```

## 2. Installing Dependencies

From the project's root folder:

```
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

This installs everything needed - pandas, scikit-learn, TensorFlow/Keras, FastAPI, uvicorn,
pytest, and a few smaller libraries. It can take a few minutes the first time, mostly because of
TensorFlow's size.

If `pip install` fails partway through, re-run the same command - pip picks up from where it left
off for packages already downloaded.

## 3. Checking the Model Files Exist

This app does not train anything - it only loads an already-trained model. Before starting the
server, check that these files exist:

```
models/lstm/model.keras
models/lstm/tokenizer.pkl
models/lstm/label_map.json
```

These were produced in Phase 5 (`notebooks/04_lstm_training.ipynb`) and are not included in the
git repository (see `.gitignore` - trained model files are intentionally left out, since they can
be regenerated by re-running the notebook). If they are missing, either copy them from wherever
Phase 5 was originally run, or re-run `notebooks/04_lstm_training.ipynb` from a fresh clone (this
does mean retraining, which normally takes about 10 minutes on a CPU-only laptop).

## 4. Starting FastAPI

With the virtual environment activated, from the project's root folder:

```
uvicorn api.app:app --reload
```

What you should see in the terminal, in order:

1. A few TensorFlow/oneDNN informational lines (these are normal, not errors).
2. `Loading LSTM model and tokenizer...`
3. `Model and tokenizer loaded - ready to serve predictions.`
4. `Application startup complete.`
5. `Uvicorn running on http://127.0.0.1:8000`

The `--reload` flag restarts the server automatically if you edit any of the Python files - handy
during development, not needed for a one-off demo (it's fine to leave it on either way).

To stop the server, press `Ctrl+C` in the terminal.

## 5. Opening the Browser

Once the server says "Application startup complete", open:

- `http://127.0.0.1:8000/app` - the web page (paste an article, click Predict)
- `http://127.0.0.1:8000/docs` - Swagger UI, to try the API directly without the web page
- `http://127.0.0.1:8000/health` - should show `{"status": "ok"}`

## 6. Running the Automated Tests (Optional)

To check that everything is working correctly without opening a browser:

```
PYTHONPATH=. pytest testing/test_api.py -v
```

(On Windows PowerShell, set `PYTHONPATH` first: `$env:PYTHONPATH = "."`, then run the same pytest
command.)

All 14 tests should pass. See `testing/testing_report.md` for what each test checks and the
results from when these tests were last run.

## Troubleshooting

**"ModuleNotFoundError: No module named 'config'" (or 'api', 'training', etc.)**
This happens when Python doesn't know the project's root folder is importable. Run commands from
the project's root folder, and set `PYTHONPATH` to `.` first:

```
PYTHONPATH=. uvicorn api.app:app --reload
```

(On PowerShell: `$env:PYTHONPATH = "."` then run the command.)

**Server starts but predictions are slow the first time**
The first prediction after starting the server can feel slightly slower because TensorFlow
finishes some internal setup on first use. This is normal - after that, predictions are fast (a
few milliseconds, well under what a web request needs).

**"FileNotFoundError" for model.keras / tokenizer.pkl**
See Step 3 above - the model files are missing. Nothing in this phase trains a model; it only
loads what Phase 5 already produced.

**Port 8000 already in use**
Something else on your machine is already using port 8000 (maybe another copy of this app is
still running). Either close that other process, or start this one on a different port:

```
uvicorn api.app:app --reload --port 8001
```

(remember to also change the port in the browser URLs above if you do this)

**Browser shows "Unable to contact server"**
This message comes from the frontend's own JavaScript when it cannot reach the API at all -
usually because the uvicorn server isn't running, or was started on a different port than the
page is trying to reach. Check the terminal running uvicorn is still open and didn't crash.

**CORS-related errors in the browser console, if opening `frontend/index.html` directly as a file**
The app already allows requests from any origin (see `api/app.py`'s CORS setup), so this
shouldn't normally happen. If it does, the simpler fix is to open the page through the server
itself (`http://127.0.0.1:8000/app`) instead of opening the HTML file directly from disk.

**TensorFlow prints warnings about GPU support on Windows**
This is expected and harmless - the project was designed to run on CPU only (see
the project specification's Dependency Management section), so these warnings can be ignored.
